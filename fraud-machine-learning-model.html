MACHINE LEARNING · FRAUD DETECTION · CLASSIFICATION

Fraud Detection Model

Building and evaluating machine-learning models to identify fraudulent transactions using transaction, customer, merchant, geographic, and behavioral features.

Python Scikit-learn Classification Feature Engineering

01 — THE CHALLENGE

Detecting fraudulent transactions without relying on a single signal

Fraudulent transactions can resemble legitimate customer activity, making simple rule-based identification difficult. Effective detection requires combining multiple transaction and behavioral characteristics to distinguish suspicious activity.

The objective of this project was to engineer useful fraud indicators, compare several classification algorithms, and identify a model capable of separating fraudulent and legitimate transactions effectively.

02 — WHAT I DID

Engineered transaction features and compared classification models

I prepared the transaction data and engineered additional features including customer age, geographic distance, transaction time, day, and week. Categorical variables such as merchant category and occupation were encoded for modelling, while numerical features were prepared for model training.

I trained and evaluated Logistic Regression, Decision Tree, K-Nearest Neighbors, and Support Vector Machine classifiers, comparing their ability to correctly identify fraudulent and legitimate transactions.

03 — KEY FINDINGS

What the model comparison revealed

0.94 Decision Tree accuracy
0.94 Decision Tree recall
0.98 ROC-AUC

Feature engineering added behavioral context

Transforming raw transaction information into customer age, geographic distance, and time-based features gave the models additional information for distinguishing transaction behavior.

Model selection required more than accuracy

I compared classification performance using precision, recall, F1 score, confusion matrices, and ROC-AUC rather than relying on accuracy alone.

The Decision Tree produced the strongest overall result

The selected Decision Tree achieved approximately 94% accuracy and recall, 95% precision, a 94% F1 score, and a ROC-AUC of approximately 0.98.

04 — WHY IT MATTERS

Fraud detection depends on identifying suspicious activity while controlling false alerts

A useful fraud model must identify as much fraudulent activity as possible while avoiding an excessive number of legitimate transactions being incorrectly flagged.

Comparing precision, recall, false positives, false negatives, and overall discrimination provides a more practical view of whether a model could support fraud monitoring and investigation workflows.
